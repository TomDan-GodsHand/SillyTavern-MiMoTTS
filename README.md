# SillyTavern-MiMoTTS

把 **小米 MiMo 语音合成**（`mimo-v2.5-tts` 系列）接入 SillyTavern 的 TTS 供应商扩展。
安装后，酒馆 TTS 面板的 Provider 下拉框里会多出 **MiMo** 一项。

> 当前版本 **v2.1.0**：新增 **音色设计（voice design）** —— 写一段描述就能设计音色，不用录样本。
> （v2.0.0 合并了原先的自用完整版：中转备用 / 分段流水线 / 5xx 重试 / 空文本保护，并带来音色克隆。）
> 此后只维护这一个仓库。

---

## 功能

| 功能 | 状态 | 说明 |
|---|---|---|
| 预置音色合成 | ✅ | `冰糖` `茉莉` `苏打` `白桦` `Mia` `Chloe` `Milo` `Dean` |
| **音色克隆** | ✅ v2.0.0 | 上传 5~15 秒 mp3/wav，零训练复刻 |
| **音色设计** | ✅ v2.1.0 | 一段自然语言描述即出音色，无需样本（每次重新设计，音色不固定） |
| 整段播放（推荐） | ✅ | 非流式拿单个完整 MP3，零卡顿 |
| 分块流式播放 | ✅ | pcm16 + 本地封 WAV，首音快但块间有停顿 |
| 分段流水线 | ✅ | 长文本按句切分、逐批请求、边到边播，抢首音 |
| 在途请求取消 | ✅ | 切换消息/停止播放时中止旧请求，避免"两条一起读" |
| 中转备用模式 | ✅ | 直连不可用时经服务器转发（**克隆与音色设计不支持**） |
| 5xx 自动重试 / 空文本保护 | ✅ | MiMo 偶发 500；整条都是元数据块时直接跳过 |

## 安装

```bash
cd <SillyTavern>/data/<user>/extensions
git clone https://github.com/ymf2317-tech/SillyTavern-MiMoTTS.git mimo-tts
```

也可以放进 `public/scripts/extensions/third-party/mimo-tts/`，然后硬刷新页面（Ctrl+Shift+R）。

## ⚠️ 先读这里：必须这样配，否则标签会被念出来

酒馆的文本清洗发生在「按段朗读」切段**之后**，而且是**逐行执行**的。
所以只要开着「按段朗读」，**跨行正则必然静默失效** —— 标签块、元数据会被一字一句念出来。

| 设置项 | 值 | 为什么 |
|---|---|---|
| **按段朗读** | **关** | 开着会让清洗逐行执行，跨行正则失效 |
| **跳过标签块内容** | **关** | 它自带的正则太粗糙，整段模式下会把正文一起吃光 |
| **应用正则过滤** | **开** | 填你需要的过滤规则（可过滤思维链、`<tag>` 块等） |
| **分段流水线**（本扩展） | **开** | 补回关掉按段朗读后损失的延迟 |
| **播放方式** | **整段播放** | 分块流式每块都要换音源，必然有间断 |

## 音色克隆

1. TTS 面板 → Provider 选 **MiMo** → 滑到「音色克隆」；
2. 选一段 **5~15 秒清晰人声**（mp3 / wav，base64 后 ≤10MB）→ 起个名字 → **添加克隆音色**；
3. 列表里可以「试听」「删除」；
4. 在 **Voice Map** 里给角色选 `[克隆] 名字`。

参考音频存在浏览器 **IndexedDB**，不会写进 `settings.json`（否则每次保存都要写几 MB）。
换浏览器/清站点数据后需要重新上传。

### 克隆的限制（官方约束，不是本扩展的偷懒）

- **不支持低延迟流式**。官方文档明确：`mimo-v2.5-tts-voiceclone` 的流式是「降级兼容模式」，
  **整段推理完成后才一次性返回**，拿不到边生成边播。所以克隆的首音注定比预置音色慢。
- **每次请求都要重传参考音频**。MiMo 没有「上传样本 → 换 voice_id」的注册接口，
  `audio.voice` 必须每次带 `data:<mime>;base64,<样本>`。
- **只能直连**。中转接口是 OpenAI 的 `/v1/audio/speech`，只能传预置音色 ID。
- 克隆模型不支持预置音色、不支持音色设计（voicedesign 是另一个模型）。

为了把首音的等待压下来，本扩展对克隆也启用**分段流水线**：第一批 20 字左右先合成先播，
后面的批次边合成边播。代价是每批重传一次样本（10 秒 mp3 ≈ 100KB，可接受）。

## 音色设计（voice design）

1. TTS 面板 → Provider 选 **MiMo** → 滑到「音色设计」；
2. 写 **1~4 句**音色描述（覆盖性别年龄、音色质感、情绪语气、语速节奏），起个名字 → **添加设计音色**；
3. 列表里可以「试听」「删除」；描述文本存在 `settings.json`（只有几十字，不需要 IndexedDB）；
4. 在 **Voice Map** 里给角色选 `[设计] 名字`。

面板上的**风格指令**如果非空，会作为语气要求一并拼进 `user` 消息交给模型（官方允许两者同放 `user`）。

### 设计音色的限制（官方约束 + 实测）

- **不能传 `audio.voice`**。官方明确 voicedesign 不支持该字段，实测带上它直接 **HTTP 400**：
  `{"error":{"code":"400","message":"Param Incorrect","param":"audio.voice is not supported for voice design model"}}`。
  所以本扩展为它单独走了一条请求路径，绝不携带 `voice`。
- **每次请求都重新设计音色**：同一段描述连续两次生成，音频长度都不一样（实测），音色**不固定**。
  想要一个长期稳定的 NPC 音色，先用它生成一段满意的音频，再把那段音频当**音色克隆**上传。
- **不能分批**：既然每次都重新设计，同一条消息分批合成会让音色中途漂移；所以设计音色固定整段一次合成，
  长文本的首音会比预置音色慢。
- **只能直连**，理由同克隆：中转接口是 OpenAI 的 `/v1/audio/speech`，没有承载音色描述的字段。
- 官方同样**没有为它提供低延迟流式**（流式是"兼容模式"，推理完才一次性返回）。
- 官方说明：不支持唱歌模式、不支持预置音色与音色复刻。

## 延迟参考（实测，2026-11）

| 场景 | 耗时 |
|---|---|
| 预置音色，40 字 | ~2.1s（很稳定） |
| 音色设计，30 字 | 2.8s ~ 3.2s（两次实测；同一描述两次输出长度不同） |
| 克隆，15 字 | 1.4s ~ 10.4s（**抖动极大**，取决于 MiMo 克隆通道排队） |
| 克隆，40 字 | ~9.9s |

结论：日常对话用预置音色；克隆只留给特定角色，且样本越短越好。

## 密钥"不保存"？大概率不是扩展的问题

酒馆保存设置的方式是**内存态整体回写 + 1 秒防抖**，且 `beforeunload` **不保存**。所以：

- 粘贴 Key 后立刻 Ctrl+R / 关页面（<1s）→ 没落盘；
- **开两个标签页**，在旧标签页改任何设置 → 1 秒后把整份旧设置写回，Key 被覆盖成空。

本扩展在面板底部加了「设置已保存 HH:MM:SS」提示，可以看到保存确实发生了。

## 开发者说明（踩坑记录）

- **流式 MP3 每块自带 Xing 头帧**：`stream:true` 时每个 SSE 块都是一个带 Xing 帧的 MP3 片段，
  拼起来就是几十个空帧 → 播放时每 0.3 秒"突"一下。所以整段播放必须走 `stream:false`；
  要分块就改用 `pcm16` 并本地封 WAV（无帧结构，可任意切割）。
- **酒馆播放器每块换一次音源**（`getBase64Async` → 换 `.src` → `canplay` → `play`），
  移动端每次 0.3~0.5s。推论：分 N 块必卡 N-1 次，零卡顿与低延迟不能兼得。
- **酒馆没有"取消"事件**：`resetTtsPlayback()` 只清队列，不会通知供应商。
  本扩展用 newest-wins：新请求一来就 `abort()` 上一个。
- **voicemap 存的是显示名，`generateTts` 收到的是 `voice_id`**，两者都要接住。
- **voicedesign 不支持 `audio.voice`**：带上它直接 400。预置/克隆都靠 `voice` 传音色，设计这条路必须完全不发这个字段，
  所以它单独走 `fetchDesignBytes`，而不是复用 `postDirect`。
- **设计音色不能分批**：它每次请求都重新设计，分批会让同一条消息里出现两种音色；`wholeTts` 的 `options.single`
  就是为它准备的（在此之前没有调用方）。
- **同一描述两次生成结果不同**（实测：同为 30 字文本，两次返回的音频分别是 69528 / 57240 字节）——
  所以设计音色的"试听"不等于"待会儿听到的就是这个"。
